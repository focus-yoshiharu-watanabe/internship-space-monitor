# スペース見守りモニター

カメラに映った人をAIが見つけて、**定員オーバー**と**離席**を画面に知らせるアプリです。
カメラ・AI・画面表示の部分はできています。みなさんが書くのは、**人数を数える関数**と**自分のルールの関数**です。

開発は **Jetson（エッジAIコンピュータ）の上** で行います。自分の PC の VS Code から Jetson に接続して、コードを書きます。
映像のウィンドウは、Jetson につながった**モニタ**に出ます。

1日目は、カメラの代わりに**練習用の動画2本**を使います（何度でも同じ映像で試せるので、直したことが効いたか確かめやすい）。
本物のカメラは、2日目に2人のコードを合体させるときに使います。

| 動画 | 中身 | 練習に使えること |
|---|---|---|
| `desk.mp4`（56秒） | 机に座った人。ときどきモニタに**人の写真**が映る | 定員オーバー（写真も人と数えられる！）／枠の「中心」と「足元」で人数が変わる |
| `office.mp4`（36秒） | ガラス越しのオフィス。1〜4人。奥の席で人が出入り | 定員の人数を変える／ぼやけて一瞬見失う → 離席を「すぐ判定しない」理由 |

## 1. Jetson に接続する（最初に1回だけ）

1. PC の VS Code に拡張機能 **Remote - SSH** を入れる
2. VS Code の左下の **`><`** を押す → **Connect to Host...** → 担当者から聞いたアドレスを入力（例：`intern1@192.168.0.114`）
3. 「Linux」を選び、パスワードを入力（担当者から聞いたもの）
4. **Open Folder** → `space-monitor` を選んで OK
5. 拡張機能 **Claude Code**（発行元 Anthropic）を入れる（「**SSH: … にインストール**」を選ぶ）
6. **`Ctrl + Shift + P`** → `Claude Code: Open` と入力 → 出てきたコマンド（例：Claude Code: Open in New Tab）を選ぶ
   （アイコンが見つからなくても、この方法なら必ず開けます）
7. 担当者がログイン済みなので、そのまま使えます。**`/logout` はしないでください**（ログインし直せなくなります）
   - もし **Sign in** の画面が出たら、担当者を呼んでください

## 2. 起動

VS Code のメニュー **ターミナル → 新しいターミナル** を開いて：

```bash
./run.sh
```

Jetson のモニタに **自分のユーザー名が付いたウィンドウ**（例：`Space Monitor intern1`）が出て、
動画の人に**緑の枠**が出れば成功です。

**止めるときは、VS Code のターミナルで `Ctrl + C`** を押します。

## 3. 画面の見方

| 表示 | 意味 |
|---|---|
| 緑の枠 | AIが見つけた物（名前と自信の度合い 0〜1） |
| 青い四角 | 見守るゾーン（`ZONE`） |
| 左上「現在 ○人」 | `count_people` が返した人数 |
| 左上「FPS」 | 1秒に何回、画面を更新できているか |
| 画面のふちの色・下のメッセージ | ルールが返した Alert |
| 右下 `x= y=` | Jetson のマウスを乗せたときの座標。`ZONE` を決めるときに使う |

## 4. ファイルと担当

| ファイル | 担当 | 中身 |
|---|---|---|
| `common.py` | **2人で** | `count_people`：ゾーンの中の人数を数える |
| `capacity.py` | 定員カウント担当 | `judge_capacity`：定員を超えたら警告 |
| `absence.py` | 離席検知担当 | `judge_absence`：一定時間いなかったら通知 |
| `app.py` | 土台 | **上の「設定」欄だけ**触ってOK（`SOURCE` は用意された2本の動画の切り替えだけ） |
| `detector.py`・`models/` | 土台 | AIの部分。触らない |

自分のルールを動かすには、`app.py` の `RULES` を自分の担当のものにします。

```python
RULES = [judge_capacity]   # 定員カウント担当
RULES = [judge_absence]    # 離席検知担当
```

## 5. 作業のルール

- **15分詰まったら相方に聞く。30分詰まったら担当者に聞く**
- 動いたら、ファイルをコピーして保存する（例：`capacity.py` → `capacity_ok1.py`）
- AI（Claude Code）に頼むのは**自分の関数1つだけ**
- AIが出したコードは「この行は何をしてる?」と**聞き返してから使う**
- エラーが出たら、AIに貼る前に「どこで何が起きたか」を口で一言説明してみる
- **`SOURCE` は用意された2本の動画のどちらかにする**（カメラは2日目に担当者と一緒に使う）
- **ライブラリをインストールしない**（Jetson の環境は2人で共有しているので、壊すと2人とも動かなくなる）

## 困ったとき

| 症状 | 対処 |
|---|---|
| 「動画ファイル … が見つかりません」 | `SOURCE` のパスが間違っていないか、README の2本の名前と見比べる |
| 「カメラ … を開けません」 | 自分のアプリがもう1つ動いていないか？ 前のターミナルで `Ctrl + C`。見つからなければ `pkill -u $USER python3` |
| 「cannot open display」などでウィンドウが出ない | 担当者を呼んでください |
| 画面に「○○ でエラー」と出る | 自分のコードで例外が起きています。**ターミナルに詳しい内容**が出ているので、それを読む（AIに貼ってもOK） |
| 「返り値が約束の形ではありません」 | Alert の形 `{"rule": ..., "level": ..., "message": ...}` になっているか確認 |
| 「level '○○' は LEVEL_COLORS にない」 | 2人で決めた level の名前と、`app.py` の `LEVEL_COLORS` がずれています |
| 動きがカクカクする | Jetson でアプリが3つ以上動いていないか確認。担当者を呼んでください |
| VS Code がつながらない | PC が Jetson と同じ Wi-Fi につながっているか確認 |

## 付録：PC だけで動かす（Jetson が使えないとき・担当者の指示があったとき）

Windows の PC で動かします。事前に Python（3.10 以上）が必要です。

1. GitHub のこのページで **Code → Download ZIP** → ZIP を右クリック → **プロパティ** →「**許可する**」にチェック → 展開
2. `setup.bat` をダブルクリック（数分）→「DONE」と出たら完了
3. `run.bat` をダブルクリックで起動。`q` キーで終了

- カメラが映らない／白黒になる：`.venv\Scripts\python find_camera.py` で番号を調べて、`app.py` の `SOURCE` を変える
- テスト動画を撮る：`.venv\Scripts\python record_video.py 0 videos/test.mp4`（`r` で録画開始／停止、`q` で終了）
